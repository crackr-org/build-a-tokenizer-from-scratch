# Build a tokenizer playground

Serve your trained tokenizer through FastAPI and deploy a browser playground for it.

It is finally time to ship our tokenizer. You built a BPE tokenizer from scratch, optimized it, scaled its training to a larger multilingual corpus, and made it compatible with `tiktoken`. But a GitHub repo is not a demo, and **every respectable side project eventually earns itself a URL.** ;)

So for the last task, we’ll put a small web interface and serve your tokenizer through an API, so that you can add it to your portfolio, send it to a potential employer, or just for the joy of putting something you built on the internet.

This is not a frontend or backend project, so I’m not going to make you spend the final task building a web app. I prepared the demo skeleton for you. It includes the UI interface, a small FastAPI backend, and the plumbing for loading a `tiktoken` encoding. You will bring the model you trained in the previous task and wire it in.

## Set up your demo

Our playground is pretty simple. You type some text and it shows how the tokenizer breaks it into tokens, their IDs, and the bytes for each token. You can see what the finished playground looks like in the [live demo](https://tokenizer-playground.onrender.com/).

**Demo repository:** [crackr-org / crackr-build-tokenizer-from-scratch-demo](https://github.com/crackr-org/crackr-build-tokenizer-from-scratch-demo)

Fork the [playground repository](https://github.com/crackr-org/crackr-build-tokenizer-from-scratch-demo) into your GitHub account, then clone your fork:

```bash
git clone https://github.com/<your-github-name>/crackr-build-tokenizer-from-scratch-demo.git
cd crackr-build-tokenizer-from-scratch-demo
```

Copy the `.tiktoken` file from the previous substage into `artifacts/`. As long as the directory contains exactly one encoding file, the filename does not matter.

Install the dependencies and start the application:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn backend.app.main:app --reload
```

Open [http://localhost:8000](http://localhost:8000). You should see your encoding filename and vocabulary size at the top. Try every language you trained on and inspect the token IDs, boundaries, and bytes that are generated by your tokenizer.

## Put it online

You can use your favorite cloud provider to deploy your demo: [Railway](https://railway.com/), [Fly.io](https://fly.io/), [Google Cloud Run](https://cloud.google.com/run), or any other host that accepts a Dockerfile. [Vercel](https://vercel.com/docs/frameworks/backend/fastapi) can host FastAPI as well.

We will use [Render](https://render.com/docs/deploy-fastapi) (we are not affiliated). It can build the Dockerfile we already set up and connect directly to GitHub. Most importantly, we tried to keep this whole project free, and Render's free web service is enough for this demo.

If you choose Render, create `render.yaml` in the root of your playground repository:

```yaml
services:
  - type: web
    name: tokenizer-playground
    runtime: docker
    plan: free
    healthCheckPath: /api/health
```

Commit and push `render.yaml` together with your `.tiktoken` file. Then open Render, choose **New → Blueprint**, connect your fork, and apply the Blueprint. Render will build the Docker image and give you a public `onrender.com` URL.

> **The cost of free**
>
> [Render's free web services](https://render.com/docs/free#spinning-down-on-idle) spin down after 15 minutes without traffic. The first visit after that can take about a minute while the service wakes up. That is a reasonable compromise for a portfolio demo.

Once it is live, try it a couple of times, copy the URL, and put it somewhere worth keeping. You built the tokenizer.
